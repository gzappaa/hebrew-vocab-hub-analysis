# hebrew-vocab-hub-analysis

Data analysis, reporting, and BI layer for [Hebrew Vocab Hub](https://github.com/gzappaa/hebrew_vocab_hub_API) — exploring vocabulary structure, source comparison, and linguistic patterns across ~13,865 Hebrew word forms scraped from songs, news, and YouTube comments.

This repo is the analyst-facing companion to two other projects:

- **[hebrew_vocab_hub_API](https://github.com/gzappaa/hebrew_vocab_hub_API)** — the FastAPI + PostgreSQL service that stores and serves the dataset (schema, search API, web UI)
- **[hebrew_vocab_hub](https://github.com/gzappaa/hebrew_vocab_hub)** — the Scrapy/Playwright scraping pipeline that builds `vocab_dataset.json` from pealim.com, Genius, Tatoeba, Reverso, and the YouTube Data API

This repo doesn't scrape or serve anything — it connects read-only to the Postgres database populated by those two projects and turns it into notebooks, a report, an Excel workbook, and a Power BI dashboard.

## Notebooks

### `01_eda.ipynb` — Exploratory Data Analysis
Baseline dataset counts, vocabulary size/structure, part-of-speech distribution, root productivity (Hebrew's root-and-pattern system), example sentence coverage, and word frequency distribution. Confirms the dataset follows Zipf's law (power-law exponent ≈ -1, close fit), with the caveat that frequencies reflect the specific scraped sources, not general spoken/written Hebrew.

### `02_source_comparison.ipynb` — Source Comparison
Compares vocabulary across songs, news, and YouTube: overlap via Venn diagram, most frequent words per source (stopwords removed), and LLM-assisted semantic register labeling (via Gemini) of the top 50 words per source into `emotional_social`, `public_formal`, `informal_everyday`, and `neutral_general`. Songs skew emotional/informal, news skews public/formal, YouTube skews emotional-reactive — consistent with each source's communicative role.

### `03_linguistic_patterns.ipynb` — Linguistic Patterns
Tests whether words appearing across multiple sources have higher frequency than single-source words. Finds a clear positive relationship (log-transformed frequency increases with source coverage), suggesting cross-domain presence is a proxy for how "common" a word is in everyday Hebrew. Closes with a full limitations/bias section (corpus representativeness, source imbalance, unvalidated LLM labels).

## Excel workbook

`excel/hebrew_vocab_hub_report.xlsx` — generated by `scripts/generate_workbook.py`, which queries the same Postgres DB directly (not a re-export of notebook outputs) so it can be regenerated independently if the dataset changes.

| Sheet | Contents |
|---|---|
| `Overview` | Row counts across all core tables |
| `POS_Distribution` | Part-of-speech breakdown with % of total |
| `Top_Roots` | Top 30 roots by number of derived lemmas |
| `Word_Frequency_Top20` | Raw top-20 words by total frequency (unfiltered) |
| `Top_Words_Overall_Filtered` | Top-20 content words, stopwords excluded |
| `Source_Overlap` | Venn segment counts (Songs only, News only, all three, etc.) |
| `Top_Words_By_Source` | Top-20 stopword-filtered words per source |
| `Semantic_Labels_By_Source` | Register label counts per source (from cached Gemini labels) |
| `Frequency_By_Coverage` | Per-word frequency + source count, for the coverage-vs-frequency finding |

Run `python scripts/generate_workbook.py` from inside `excel/` (relies on `../data/stopwords.txt` and `../data/word_semantic_labels.csv`).

## Power BI dashboard

`powerbi/hebrew-vocab-hub-analysis.pbix` (+ exported `.pdf` for viewing without Power BI Desktop — no Pro/student license was used, so nothing is published online).

- **Page 1 — Overview:** KPI cards (vocabulary size, word forms, conjugations, roots), part-of-speech pie chart, most productive roots bar chart
- **Page 2 — Vocabulary:** Treemap of top overall content words, plus three source-specific bar charts (Songs / News / YouTube)
- **Page 3 — Source Comparison & Patterns:** Vocabulary overlap across sources, semantic register by source (stacked bar), word frequency by source coverage

Data source: `excel/hebrew_vocab_hub_report.xlsx`.

## `data/`

- `stopwords.txt` — Hebrew stopword list used for content-word filtering
- `word_semantic_labels.csv` — cached Gemini-generated register labels (top 50 words × 3 sources), kept so re-running notebooks/scripts doesn't re-spend API calls
- `hebrew_vocab_dashboard.csv` — flat export used by `scripts/export_dashboard_dataset.py`

## `scripts/`

- `generate_workbook.py` — builds the 9-sheet Excel workbook directly from Postgres
- `export_dashboard_dataset.py` — supplementary dataset export for the dashboard

## Setup

Requires read access to the same PostgreSQL instance populated by [hebrew_vocab_hub_API](https://github.com/gzappaa/hebrew_vocab_hub_API).

```bash
pip install -r requirements.txt
```

Create a `.env` with:

```env
DB_USER=
DB_PASSWORD=
DB_HOST=
DB_PORT=
DB_NAME=
GEMINI_API_KEY=   # only needed if regenerating semantic labels from scratch
```

Then run notebooks from `notebooks/`, or regenerate the Excel workbook from `excel/` via `generate_workbook.py`.
